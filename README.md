# Solar Monitor

家庭用太陽光発電・蓄電池のデータを記録し、PCやタブレットのブラウザで表示するアプリです。SHARP SUNVISTA JH-RWL8環境を対象に開発しています。他機種での動作は未確認です。

このREADMEはソースコード版0.9.13の機能を説明しています。公開済み配布物の機能・確認状況は、各バージョンのリリースノートを参照してください。

## ダウンロードと起動

公開済みのWindows x64版は [GitHub Releases](https://github.com/takemontakashi2/solar-monitor/releases) から取得できます。zipを展開し、exeのあるフォルダーでPowerShellを開いて起動してください。

以下の例ではexeの名前を `solar-monitor.exe` としています。バージョン付きのファイル名の場合は、実際の名前に読み替えてください。

```powershell
.\solar-monitor.exe
```

初回起動時に同じLAN内のモニターを自動探索し、接続先を `data/config.json` に保存します。次回以降は保存した接続先を使います。データは `data/solar.db` に保存します。SQLiteの別途インストールは不要です。

PCのブラウザで [http://localhost:8080/](http://localhost:8080/) を開きます。同じLANのタブレットからは、次のアドレスを開いてください。

```text
http://<アプリを起動したPCのIPアドレス>:8080/
```

アプリは起動したままにしてください。終了するにはPowerShellで `Ctrl+C` を押します。

## Raspberry Piでの起動と保存間隔

次回リリースから、初代Pi Zero / Zero Wと32bit OS向けの `linux-armv6`、Pi Zero 2 Wなどの64bit OS向けの `linux-arm64` を配布します。対応するアーカイブを展開して、実行ファイルのあるディレクトリで起動します。

```sh
# ファイル名は配布されたバージョンに合わせてください
chmod +x solar-monitor-0.9.13-linux-armv6
./solar-monitor-0.9.13-linux-armv6 -flush-interval 1h
```

`-flush-interval 1h` を指定すると、計測結果をメモリに保持し、起動後1時間ごとにまとめてDBへ保存します。計測時刻と各回の値をそのまま記録し、保存前でもグラフ・カード・統計に表示します。この指定はWindowsでも使えます。指定しない場合（`0`）は従来どおり計測ごとに保存します。

- `Ctrl+C` やLinuxの通常の停止（SIGTERM）では、残っているデータを保存して終了します。終了メッセージを待ってください。
- 電源断・強制終了では未保存データを失います。1時間間隔なら通常は最大1時間分、保存障害が続いた場合はそれ以上が未保存になります。
- 未保存サンプルのJSON換算が16 MiBを超える前には、指定時刻より早く保存します。実際のメモリ使用量はこの値より多くなります。
- 保存失敗時は未保存データを保持して次の保存時刻に再試行します。上限到達時に保存できなければ、新たな計測を一時停止し、30秒ごとに保存を再試行します。
- 固定項目の取得済み情報もまとめて保存し、取得不可項目の一覧は変更時だけDBを更新します。書き込み回数の削減率と、SDカードの消耗の削減率は同じではありません。

Pi実機での動作は未確認です。自動起動を含む常設用インストールセットは1.0で対応予定です。

## 画面の使い方

- 上段に発電・消費・買電/売電・今日の発電を表示します。
- 歯車アイコンから追加の表示項目を選択できます。選択はブラウザごとに保存します。
- 選択したカードは未取得でも表示し、値を `--` にします。メーカー情報や定格値は初回取得後に保存し、再起動後も保存値を表示します。その他の項目で最後の取得値を表示する場合は取得時刻を添え、「前回値」「更新待ち」で更新状況を示します。
- グラフは選択した日付の0時〜24時を表示します。「前日」「翌日」または日付入力で過去の記録へ移動でき、「今日」で戻れます。移動先の日に記録がない場合、その方向のボタンは表示しません。日付入力では任意の日を選べます。上部のカードは最新値を表示します。
- 「前日のデータを点線で重ねる」で、選択日の前日と同じ時刻で比較できます。記録がない日は「記録なし」と表示します。左軸は電力（kW）、右軸は電池残量（0〜100%、左軸と0点を共通化）、横軸は時刻です。電池残量は各取得時点の実測値を表示し、電力の5分平均の対象にはしません。
- グラフは標準で5分移動平均を使い、「実測値」に切り替えられます。買電はプラス、売電はマイナスで表示し、0の線を基準に区別します。5分平均も符号付きで計算するため、期間内の買電と売電は相殺されます。欠測を挟む5分以内の区間は破線でつなぎ、5分を超える空白はつなぎません。平均は直近5分の取得済みの値から計算します。表示モードの選択はブラウザに保存されます。

凡例をクリック（タップ）すると、その線を太く、他の線を薄く表示します。同じ凡例をもう一度選ぶと解除します。

機器の状態カードは、全機器の状態が取得できていて異常がない場合に折りたたみます。見出しを押すと詳細を開けます。異常発生時や未取得・5分以上更新されていない場合は自動で開きます。

## 接続先とポートの変更

自動探索で接続できない場合は、モニターのIPアドレスを指定します。以下のアドレスは例です。指定した接続先は保存されます。

```powershell
.\solar-monitor.exe -echonet-addr 192.168.100.202
```

画面のポートを変更する場合:

```powershell
.\solar-monitor.exe -addr :8081
```

この場合、ブラウザでもポート `8081` を指定してください。機器との通信にはUDP 3610、ブラウザからの接続には指定したHTTPポートを使います。接続できない場合はLAN接続とファイアウォール設定を確認してください。

認証・TLS機能はありません。家庭内LANでの利用を想定しています。

## 更新とバージョン確認

更新時はアプリを停止し、`data/` フォルダーをバックアップしてからexeを差し替えてください。同じフォルダーから起動すると既存の設定と記録を引き継ぎます。ブラウザも再読み込みしてください。

```powershell
.\solar-monitor.exe -v
# または
.\solar-monitor.exe --version
```

## WindowsからRaspberry Piへのデータ移行

SQLiteのDBはOS間で共通なので、Windowsで取った記録をRaspberry Piで引き継げます。

1. 移行元を `Ctrl+C` で終了し、保存が完了してプロンプトに戻るまで待ちます。保存エラーが出た場合は、移行前に解消してください。
2. 移行先のアプリも停止します。既存の記録がある場合は先にバックアップしてください。コピーはDB同士の統合ではなく置き換えです。
3. 移行元の `data/` フォルダーを丸ごと移行先へコピーします。`solar.db-wal` などの補助ファイルが残っている場合も一緒に移します。
4. 同じ版または互換性のある新しい版の実行ファイルを使い、コピーした `data/` の親ディレクトリから起動します。

既定の保存先は実行ファイルの位置ではなく、起動時の作業ディレクトリからの相対パスです。`-data` / `-config` を指定していた場合は、その保存先からDBと設定を移し、移行先のパスを指定してください。

起動中のDBだけをコピーすると、メモリやWALに残ったデータを引き継げない場合があります。移行元のバックアップは、移行先で過去のグラフと新しい記録を確認するまで残してください。同じLANなら接続先を記録した `config.json` も利用できます。カードの選択やグラフの平均設定はブラウザ保存のため、DBのコピーでは移りません。
