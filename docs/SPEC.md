# Solar Monitor 仕様書

この文書は、これまでの要望と実装方針を仕様として整理したものです。

## 目的

自宅の太陽光発電、蓄電池、関連機器のデータを自動取得して記録し、タブレットやPCのブラウザから確認できるようにする。

## 基本方針

- Go製のシングルバイナリとして動作すること。
- 外部サービスに依存せず、家庭内LANで完結して動作すること。
- データ保存はSQLiteを使うこと。
- SQLiteドライバはpure Go実装を使うこと。
- 取得できる実機データは、表示するかどうかに関係なく可能な限り保存すること。
- 表示側では、保存済みデータのうち何を見るかを選択できること。
- GitHubでバージョン管理すること。

## 対象環境

- 対象機器: SHARP SUNVISTA JH-RWL8 系のモニター環境
- 実機IPアドレス: `192.168.100.202`
- 通信方式: ECHONET Lite
- UDPポート: `3610`
- サーバ実行環境: 家庭内LAN上のPC、Raspberry Pi等
- 閲覧端末: タブレット、PCブラウザ等

## 開発・調査に使うパッケージ

ビルドに最低限必要なもの:

- Go
- Git

調査や運用確認にあると便利なもの:

- `jq`: JSONの確認、ECHONET Device Descriptionの抽出、APIレスポンス確認
- `sqlite3`: 保存済みSQLite DBの直接確認
- `curl`: HTTP APIの動作確認
- `unzip`: 添付ファイルやECHONET公式配布zipの展開

ネットワーク調査にあると便利なもの:

- `tcpdump`: UDP 3610 の送受信確認
- `netcat` または `nc`: 簡易的な通信確認

コード検索にあると便利なもの:

- `ripgrep` (`rg`): 高速検索用。環境によってはパッケージが提供されていないため必須ではない。

Debian/Ubuntu系での例:

```sh
sudo apt install git jq sqlite3 curl unzip
```

ネットワーク調査も行う場合:

```sh
sudo apt install tcpdump netcat-openbsd
```

## 実機で確認済みのECHONET Lite情報

検出済みEOJ:

- `05ff01`: コントローラー
- `027901`: 太陽光発電
- `027d01`: 蓄電池

EPC名の参照元:

- ECHONET Lite Web API Device Description v1.7.0
- `pvPowerGeneration.json`
- `storageBattery.json`
- `lvSmartElectricEnergyMeter.json`
- `controller.json`

候補特定で特に見る標準EPC:

- `027901:e0`: 瞬時発電電力計測値
- `027901:e1`: 積算発電電力量計測値
- `027901:e3`: 積算売電電力量計測値
- `027d01:d3`: 瞬時充放電電力計測値
- `028801:e7`: 瞬時電力計測値

通信上の注意:

- 実機との通信では、ローカル側もUDP `:3610` にbindする必要がある。
- 任意の送信元ポートからの要求では応答が取れない場合がある。
- マルチキャスト探索はネットワーク機器やWi-Fi設定により遮断される場合がある。
- IPが分かっている場合は、指定IPへの直接スキャンを使えること。

## データ取得仕様

### 起動時

- `-source echonet` でECHONET Lite実機から取得する。
- `-echonet-addr` が未指定の場合は探索を試みる。
- 初回取得時は、取得できるプロパティをできるだけ拾うためフルスキャンする。
- 2回目以降は通常取得として、軽めのバッチ取得にする。
- `-full-scan` 指定時は毎回フルスキャンする。

### 保存

- サンプル時刻、代表値、全ECHONETプロパティをSQLiteに保存する。
- 表示対象として選ばれていないプロパティも保存する。
- 後から消費、売電、蓄電池電力などの候補を分析できるよう、生値、数値化した値、説明値を保存する。

### 代表値

現時点で確定済み:

- 発電: `027901:e0`
- 今日の発電量: `027901:e1` に `0.001` を掛けた値

未確定:

- 消費
- 買電/売電
- 蓄電池充電/放電電力

未確定値は、保存済みプロパティの診断結果を見ながら候補EPCを特定する。

## 表示仕様

### ダッシュボード

- ブラウザで表示できること。
- タブレットで見やすいこと。
- 上部に主要カードを表示すること。
  - 発電
  - 消費
  - 買電/売電
  - 今日の発電
- 時系列グラフを表示すること。
- グラフの横軸には時刻を表示すること。
- 欠損している代表値は `0` ではなく未取得として扱い、画面では `--` 表示にすること。

### 表示する値の選択

- ECHONETプロパティは機器ごとにグループ分けして表示すること。
- 表示対象はチェックボックスで選択できること。
- 選択状態はブラウザ側に保存し、再表示時も維持すること。
- 選択画面は普段は非表示にすること。
- 右上の設定ボタンで選択画面を開閉できること。

### 診断表示

- 消費、売電/買電、蓄電池電力の候補を探すため、候補診断を表示できること。
- 診断ではEPCごとに以下を見ること。
  - 最新値
  - 最小値
  - 最大値
  - 変化量
  - 幅
  - 出現回数
- 変化幅が大きいものを優先的に確認できること。
- 診断表示は設定画面内に置き、通常表示を邪魔しないこと。

## 性能仕様

- 通常の画面表示では、全プロパティを毎回取得しないこと。
- グラフ用APIは軽量な時系列データのみ返すこと。
- 通常表示では、選択済みプロパティだけ取得すること。
- 全プロパティ一覧や診断情報は、設定画面を開いたときだけ取得すること。
- データが増えても初期表示が極端に遅くならないこと。

## API仕様

### `GET /api/samples`

グラフ用の軽量時系列データを返す。

- `limit`: 取得件数。既定値は `288`。
- 通常は詳細プロパティを含めない。

### `GET /api/properties`

最新または直近サンプルのプロパティを返す。

- `limit`: 対象サンプル数。
- `keys`: `EOJ:EPC` のカンマ区切り。指定時はそのキーだけ返す。

### `GET /api/property-stats`

保存済みプロパティの診断用集計を返す。

- `limit`: 集計対象にする直近サンプル数。
- 変化幅が大きい順に返す。

## 運用仕様

- データを蓄積するため、サーバは起動しっぱなしにするのが望ましい。
- サーバ停止中のデータは取得できない。
- 実装更新後は、新しいバイナリでサーバを起動し直す必要がある。
- 起動中の既存プロセスは、ビルド済みバイナリを差し替えても自動更新されない。

## 参考になった実機モニター値

2026-10-03 10:55 頃のSHARPモニター表示:

- 発電: `5.09 kW`
- 蓄電池充電: `3.24 kW`
- 消費: `1.71 kW`
- 売電: `0.14 kW`
- 積算発電量: `11.7 kWh`
- 積算消費量: `16.3 kWh`
- 自給率: `71%`

この時点では以下の関係が成り立つ。

```text
発電 5.09 ≒ 消費 1.71 + 蓄電池充電 3.24 + 売電 0.14
```

候補診断では、この時刻前後に `5090`、`3240`、`1710`、`140` 付近の値を持つEPCを重点的に確認する。

2026-10-03 11:56 頃のSHARPモニター履歴表示:

- 積算発電量: `15.6 kWh`
- 積算消費量: `20.2 kWh`
- 自家消費量: `14.9 kWh`
- 自給率: `77%`

履歴画面に表示される「外部発電量」は、エネファーム等の外部発電機器からの発電量を指す想定で、売電/買電とは別扱いにする。
売電/買電の候補EPCを探す際には、「外部発電量」ではなく系統側の瞬時電力または積算電力量に相当する値を確認する。
